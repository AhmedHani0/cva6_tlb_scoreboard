1. First error: generate-loop exploded in cva6_tlb.sv
Error
-E- LoopUnfold - cva6_tlb.sv:179 loop unfolding generate-loop reached 300 iterations.
What it looked like
OneSpin complained about a generate loop:

for (w_gen = 0; w_gen < CVA6Cfg.PtLevels - 1; w_gen++)
Real cause

We were elaborating cva6_tlb directly:

set_elaborate_option -golden -top {Verilog!work.cva6_tlb}

So the TLB used its default config:

CVA6Cfg = config_pkg::cva6_cfg_empty

Fix

Do not elaborate the parameterized CVA6 module directly.

Instead, create a small formal top:

cva6_tlb_formal_top
   |
   +-- i_cva6_tlb : cva6_tlb

and pass a real CVA6Cfg.

formal strategy:

small wrapper
only the DUT under verification
only required parameters/types/signals
then bind the scoreboard


5. Fifth error: config file existed, but config values were still zero
Error

Again:

vpn/asid/vmid range 4294967295 downto 0
Real cause

We read an MMU-disabled or incomplete config first:

cv32a60x_config_pkg.sv

For TLB verification, we needed a virtual-memory-enabled config, such as:

cv64a6_imafdc_sv39_config_pkg.sv

But even after reading the SV39 config, using this directly was still not enough:

parameter config_pkg::cva6_cfg_t CVA6Cfg = cva6_config_pkg::cva6_cfg;

because cva6_config_pkg::cva6_cfg is the user config, not the fully built internal config.

Fix

Read the config builder:

read_verilog -sv $CVA6_RTL_ROOT/include/build_config_pkg.sv

and use:

parameter config_pkg::cva6_cfg_t CVA6Cfg =
    build_config_pkg::build_config(cva6_config_pkg::cva6_cfg);
Lesson for future modules

CVA6 often needs this chain:

config_pkg.sv
    defines config types

cv64a6_imafdc_sv39_config_pkg.sv
    selects user config

build_config_pkg.sv
    computes final derived config

CVA6Cfg
    final complete config used by RTL

So for future modules, if derived fields are zero, check whether you forgot:

build_config_pkg::build_config(...)

6. Sixth error: type parameters through bind
Error
DeclError - illegal usage of parameter 'pte_cva6_t'
Real cause

The scoreboard bind tried to pass type parameters:

.pte_cva6_t       (pte_cva6_t),
.tlb_update_cva6_t(tlb_update_cva6_t),

These are not normal value parameters. They are SystemVerilog type parameters.

OneSpin accepted normal parameters like:

.CVA6Cfg(CVA6Cfg)
.TLB_ENTRIES(TLB_ENTRIES)
.HYP_EXT(HYP_EXT)

but rejected forwarding DUT-local type parameters through a bind.

Fix

Flatten the scoreboard interface.

Instead of:

input tlb_update_cva6_t update_i
input pte_cva6_t lu_content_o

use:

input logic update_valid_i
input logic [CVA6Cfg.VpnLen-1:0] update_vpn_i
input logic [CVA6Cfg.ASID_WIDTH-1:0] update_asid_i
input logic [PTE_WIDTH-1:0] update_content_i

and connect fields in the bind:

.update_valid_i  (update_i.valid),
.update_vpn_i    (update_i.vpn),
.update_asid_i   (update_i.asid),
.update_content_i(update_i.content),
